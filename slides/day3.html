Storage and databases

A container's files die with it

  • The writable layer from Monday is deleted with the pod. A restarted Postgres would start empty.
  • A volume is a folder mounted into the container that lives outside it.
  • You have used two kinds already: configMap and secret.
VolumeLives as long as
emptyDirthe pod
configMap, secretthe object
persistentVolumeClaimuntil you delete the claim

Asking for disk

PersistentVolumeClaim"1Gi, ReadWriteOnce"
→
StorageClass standardknows how to make disks
→
PersistentVolumethe actual disk
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: postgres-data
spec:
  accessModes: ["ReadWriteOnce"]
  resources:
    requests:
      storage: 1Gi
  • You ask for a size. The StorageClass creates the disk.
  • On kind it is a folder on a node. On AWS the same YAML gets an EBS volume.
  • ReadWriteOnce: one node at a time.

Databases in Kubernetes

In production

Your database is a managed service (RDS, Azure SQL). The app gets its connection string from a Secret. Nothing else changes for you.

StatefulSets run clustered databases inside Kubernetes. That is platform work, and out of scope.

In Lab 6

kind: Deployment
spec:
  replicas: 1
  strategy:
    type: Recreate

One replica and Recreate, so two Postgres pods never share the data folder.

Jobs: run once, then stop

apiVersion: batch/v1
kind: Job
metadata:
  name: migrate
spec:
  backoffLimit: 3
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: migrate
          image: ghcr.io/amirilovic/k8s-training-app:v1
          args: ["migrate"]
  • A Deployment keeps pods running. A Job runs one to completion and retries on failure.
  • Same image as the app, different argument: migrate applies the EF Core migrations and exits.
  • A CronJob creates a Job on a schedule.

Autoscaling

The HorizontalPodAutoscaler

kubeletmeasures pods
→
metrics-serverkubectl top
→
HPAevery 15 s
→
Deploymentreplicas: 2 … 6
  • The HPA only changes one number: the Deployment's replicas.
  • It adds pods, not nodes. When nodes are full, new pods stay Pending. The cluster autoscaler adds nodes, and that is a platform job.

How it decides

utilization = CPU used ÷ CPU request

desired = ceil( current × utilization ÷ target )

3 pods at 150% with a 50% target: 3 × 150 ÷ 50 = 9, capped at maxReplicas: 6.

  • Utilization is relative to the request, not the limit. No CPU request, no autoscaling.
  • Scaling up is fast. Scaling down waits 5 minutes by default, so a short dip does not remove pods.
  • In the lab it went from 2 to 6 pods in about 30 seconds.
  • Observed on kind: CPU went up to 467% of the request before the new pods came up, then scaled back to 2 about a minute after the load stopped with a 30 s window.

An HPA in YAML

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 6
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 50 }
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 30
  • Remove replicas from the Deployment once an HPA owns it, or every apply resets the count.
  • The 30-second window is for the lab, so you see it scale down before lunch.

Helm

A chart is templates plus values

templates/deployment.yaml, service.yaml, …
values-prod.yamlreplicas: 3, host: prod.localhost
→
helm installrenders
→
release "web"plain Kubernetes objects
spec:

  template:

  • One chart, many environments: only the values file changes.
  • Helm remembers every release, so helm rollback works like rollout undo, for everything at once.

Helm commands

helm repo add traefik https://traefik.github.io/charts
helm install traefik traefik/traefik --version 41.6.1 \
  -n traefik --create-namespace -f setup/traefik-values.yaml

helm install web ./web -n web-dev --create-namespace \
  -f web/values-dev.yaml
helm upgrade web ./web -n web-dev -f web/values-dev.yaml \
  --set image.tag=v2
helm history web -n web-dev
helm rollback web 1 -n web-dev

  • Always pin --version.
  • helm template prints the YAML without installing. Use it when a template does not do what you expect.

Ingress

One entry point, routed by host and path

browserapp.localhost:30081
→
Traefikingress controller, NodePort 30081
→
Service webhost app.localhost
Service web-v2host v2.localhost
→
pods
  • An Ingress is a set of routing rules. It does nothing without a controller that reads it.
  • Apps keep ClusterIP Services. Only the controller is exposed.
  • Chrome and Edge send any *.localhost name to your own machine, so no hosts file edits.

An Ingress in YAML

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web
spec:
  ingressClassName: traefik
  rules:
    - host: app.localhost
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web
                port: { number: 80 }

ingressClassName picks the controller. Older charts use an annotation instead:

metadata:
  annotations:
    kubernetes.io/ingress.class: alb

Most Ingresses in Epic's clusters still use the annotation, with AWS ALB or Traefik as the controller.

Controllers differ in the annotations

annotations:
  alb.ingress.kubernetes.io/scheme: internal
  alb.ingress.kubernetes.io/target-type: ip
  alb.ingress.kubernetes.io/healthcheck-path: /readyz
  alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:…
  • The Ingress spec only covers hosts, paths and TLS.
  • Everything else (health checks, certificates, auth) is an annotation that one controller understands.
  • That is why Ingress files look different in every company, and why the Gateway API exists.

The Gateway API in two minutes

GatewayClasswhich implementation · platform
Gatewayports, TLS · platform team
HTTPRoutehosts, paths, weights · your team
  • The successor of Ingress. Traffic splits and header matching are in the spec, not in annotations.
  • ingress-nginx, the controller in most older tutorials, is retired.
  • In Lab 10 step 6 you send 90% to v1 and 10% to v2 with one HTTPRoute.

.NET behind a proxy

Behind Traefik or an ALB, ASP.NET Core sees the proxy's address and http, even when the browser used HTTPS.

Redirects, generated links and OAuth callbacks then point to the wrong place.

env:
  - name: ASPNETCORE_FORWARDEDHEADERS_ENABLED
    value: "true"

This makes ASP.NET Core read the X-Forwarded-For and X-Forwarded-Proto headers the proxy adds.
